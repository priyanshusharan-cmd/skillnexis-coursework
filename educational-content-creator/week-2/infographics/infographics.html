Read any Python error in 3 steps

A traceback reads bottom to top: the bottom is where it broke.

Traceback (most recent call last): File "report.py", line 8, in <module> ③ report("Meera", []) File "report.py", line 2, in average ② return sum(scores) / len(scores) ~~~~~~~~~~~~^~~~~~~~~~~~~ ZeroDivisionError: division by zero ①
1

Read the last line

Error type + message. ZeroDivisionError: division by zero already tells you the cause.

2

Go up to the file and line

The lowest File … line N is where it crashed. The ^~~ marks point at the exact part.

3

Follow the chain to your code

Each pair of lines is one function call. The top one is where it started; the real bug is often there (here: an empty list).

Loops

for or while?

Both repeat code. Pick by what you know before the loop starts.

for

for score in scores: print(score)
Use when
  • you have a collection
  • or know how many times
take the next item
↓
run the body
↓
stops by itself when items run out

while

while balance > 0: balance -= 100
Use when
  • you repeat until a condition changes
  • count is unknown
check the condition
↓
run the body
↓
you must change something, or it never stops
Rule of thumb: if you can say “for each …”, use for. If you'd say “until …”, use while.
