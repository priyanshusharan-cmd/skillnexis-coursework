# Channel plan: Code in Small Steps

## Niche and promise
Practical programming fundamentals for learners who can spare ten minutes at a time. Each lesson ends with one small exercise and a visible result. Positioning: “Understand one useful coding idea, then practice it in a tiny program.”

## Audience personas (planning assumptions)

**Aarav, first-year student:** knows basic computer use, is unsure how to start coding, wants examples that run locally, worries about setup errors. Watches short explainers on mobile and saves code snippets. Trigger: a lab assignment due soon. Success: can explain and modify the example himself.

**Meera, career switcher:** has spreadsheet experience and limited study time, wants a portfolio, worries that tutorials skip practical details. Uses YouTube playlists and GitHub on a laptop. Trigger: a small project connected to her work. Success: a finished, documented exercise.

## Content pillars
1. Programming foundations (variables, conditions, loops).
2. Debugging and setup (read an error, isolate a cause).
3. Small projects (calculator, CSV summary, form validation).

## Competitor review method
Review three current channels in the same niche. Record recent upload date, format, title promise, audience level, and one gap from public videos. Do not infer views or search volume without checking current public data. Comparison worksheet: channel, lesson format, strengths, gap, source URL, review date.

## One-month publishing calendar
| Week | Topic | Format | Hook | CTA | Measure |
|---|---|---|---|---|---|
| 1 | Variables and types | 5-minute lesson | Why does `"5" + "2"` differ from `5 + 2`? | Try three values | Completion rate |
| 1 | Read an error message | Screen tutorial | Start with the last line | Share one error | Saves/comments |
| 2 | If/else decision | Worked example | Make a grade checker | Change the thresholds | Exercise attempts |
| 2 | Loop counter | Animated walkthrough | Repeat without copy/paste | Predict the output | Retention |
| 3 | Functions | Lesson + exercise | Name one job per function | Refactor a script | Exercise attempts |
| 3 | CSV summary | Mini project | Turn rows into a total | Download sample data | Click-through |
| 4 | Debugging checklist | Short checklist | Reproduce before fixing | Use the checklist | Saves |
| 4 | Build a small calculator | Project | Four operations, one menu | Fork the starter | Project completions |

## Editorial and quality checklist
Confirm the learning objective, verify every code example locally, show expected output, add captions, cite reused assets, include an exercise, and provide a correction note if an error is found. Track retention, completion, useful comments, and exercise attempts rather than raw views alone.
