# Three five-minute lesson scripts

## 1. Variables: labeled boxes for values (about 5 min)
**Hook (0:00):** “Why can a program add 5 and 2 but join the text `5` and `2`?”
**Objective:** explain variable, value, and basic type.
**Demo (0:30):** show `age = 18`, `name = "Mina"`, and `price = 2.5`; label each variable and type.
**Contrast (1:40):** compare `5 + 2` with `"5" + "2"`; explain that strings hold text while integers hold whole numbers.
**Try it (2:40):** ask viewers to store two numbers and print their sum. Pause, then show a solution.
**Common error (3:45):** show a misspelled variable and explain that names must match exactly.
**Recap and CTA (4:30):** “A variable name points to a value; types affect what operations mean. Change the numbers and predict the result.”

## 2. If/else: let the program choose (about 5 min)
**Hook:** “How can one small program give different feedback for different marks?”
**Objective:** use a condition to select a branch.
**Demo:** start with `mark = 76`; test `mark >= 50`; print pass or try again. Explain true/false.
**Boundary:** change 50 to 49 and then 50; verify the exact boundary.
**Practice:** add an A grade for marks at least 90. Ask which condition should be checked first.
**Common error:** use `=` for assignment instead of `==` for equality; show the language-specific correction.
**Recap/CTA:** test 49, 50, and 90, then explain why each output appears.

## 3. Loops: repeat a task with a rule (about 5 min)
**Hook:** “Would you write the same print statement one hundred times?”
**Objective:** understand initialization, condition, and update.
**Demo:** trace `for i in range(1, 6)` on screen; show each value and output.
**Practice:** change the range to print 2, 4, 6, 8, 10. Explain step size.
**Debug moment:** remove the update from a while loop and explain why it may never end; restore a safe condition.
**Recap/CTA:** viewers predict the output before running the loop.
